# WaGo Android Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, or superpowers:subagent-driven-development if the user chooses delegation.

**Goal:** Make the existing Android client usable for messaging, attachments and voice notes with a comfortable Spanish mobile UI.

**Architecture:** Preserve Go/Gio and hypermeow. Isolate Android system integration behind platform files; keep protocol types out of UI and deliver asynchronous results on the UI goroutine.

**Tech Stack:** Versions pinned in go.mod; Gio v0.10.3, Go 1.27, Android SDK/NDK, Storage Access Framework, malgo and Ogg/Opus.

**Spec:** ../specs/2026-10-13-android-design.md

## Global Constraints

- Preserve sessions, desktop behavior and low memory use; no WebView or Electron.
- APK ARM and ARM64, minimum SDK 21, target SDK 35, application ID com.muleff.wago.
- Four labeled mobile destinations; 48 dp touch targets; roughly 16 sp body text.
- Read the source/docs for pinned APIs before implementation.
- Do not translate message content, names, phone numbers or URLs.
- Never write credentials to repository or logs; actual WhatsApp reception needs an authorized session and recipient.

## Review Focus

- Cloud document providers can return unknown size or misleading filenames: stream into private cache safely.
- Activity destruction during permission or picker requests must not strand goroutines.
- Rapid cancel/send/switch-chat during capture must not send audio to a different chat.
- Playback underflow, end of stream and seek must not deadlock or report false completion.
- Long names, digit-only contacts and large system text must not break mobile layout.

## Task 1: Build baseline and Android integration contract

**Files:** `.github/workflows/build.yml`, `patches/apply.sh`, new `internal/androidbridge/bridge_android.go` and `bridge_test.go`; packaging-specific Java/C files as determined by pinned gogio source.

**Interfaces:** Produce `RequestMicrophone(ctx context.Context) error`, `PickFiles(ctx context.Context, multiple bool, mimeTypes []string) ([]PickedFile, error)` and `OpenMedia(path, mime string) error` in androidbridge. `PickedFile` contains `Path`, `Name`, `MIME` strings. Returned paths are app-owned cached copies. Only Android packages consume this interface.

- [ ] Locate/install a compatible Go toolchain and Android SDK/NDK; read pinned Gio packaging/JNI source to select supported integration hooks.
- [ ] Apply patches; run `go mod verify`, `go test ./...`, `go vet ./...` and `go build ./...`; record baseline failures separately.
- [ ] Add tests for bridge request completion/cancellation: permission denial returns an error, picker cancellation returns no files, destroyed activity completes pending requests with an error, duplicate results are ignored.
- [ ] Run those tests and demonstrate failure before implementing request bookkeeping and native callbacks.
- [ ] Implement Android-thread scheduling, request IDs and lifecycle cleanup using supported pinned hooks; rerun tests and build Android entry point.
- [ ] Commit the verified platform integration.

## Task 2: Native attachment selection and media opening

**Files:** `internal/filepick/filepick_other.go`, new `filepick_android.go`; `internal/ui/attach.go`, `sendview.go`, `open.go`; bridge files from Task 1.

**Interfaces:** Preserve `filepick.Open(title string, multiple bool, filters ...Filter) ([]string, error)`. Android maps filters to MIME types and uses Task 1. Mark Android-picked files as temporary through the existing `pickResult.temp` and `attachFile.temp` ownership mechanism. Desktop-selected files remain user-owned.

- [ ] Add failing tests covering multiselect, cancellation, unknown provider size, unsafe display names, interrupted copy and cleanup on preview cancellation/sending failure.
- [ ] Run targeted tests and confirm failure; implement SAF content copying with fixed-size buffers, descriptor closure and partial-copy cleanup.
- [ ] Exclude Android from desktop dialog implementation; connect file selection to current send preview and retain file metadata for attachment classification.
- [ ] Implement Android opening of media unsupported by internal player using a granted content URI, never a raw private file URI.
- [ ] Run filepick/UI/backend attachment tests; on emulator select image, video, audio and document, cancel selection and preview, and confirm cache cleanup.
- [ ] Commit attachment integration.

## Task 3: Permission, capture and playback lifecycle

**Files:** `internal/voicerec/micpermission_other.go`, new `micpermission_android.go`, `voicerec.go`, `capture_android.go`, tests; `internal/video/video_android.go`, tests; `internal/ui/voicerecord.go`.

**Interfaces:** Keep `Start(ctx context.Context) (*Recorder, error)`, `Finish() (string, error)` and `Abort()`. Route Android permission requests through Task 1 using the recording context. Keep existing Player commands/status API.

- [ ] Add failing tests for cancellation while requesting permission, denial without capture, finish after queued PCM, repeated abort, chat switch and shutdown during recording.
- [ ] Run tests; request microphone permission before device initialization, stop capture before flushing encoder, close resources in dependency order and clean failed/aborted files.
- [ ] Add playback tests for full queue plus pause/close, seek at EOF, underflow and replay; assert command completion and progress derived from consumed samples.
- [ ] Run tests, repair command responsiveness and status publication, and verify generated Ogg has Opus headers, valid termination and expected duration.
- [ ] On emulator verify grant/deny, record/send preview, discard, playback, background/foreground and resource release. Report actual microphone/device limitations explicitly.
- [ ] Commit audio changes.

## Task 4: Mobile navigation, details and typography

**Files:** `internal/ui/mobile.go`, new `mobile_updates.go`, `app.go`, `info.go`, `contactinfo.go`, `theme.go`, `fonts.go`; mobile layout/back/typography tests.

**Interfaces:** Add `layoutMobileUpdates(gtx C) D` for states and channels in one mobile destination. Preserve backend model and desktop pages. Centralize mobile back handling in `mobileBack() bool`: true when an in-app layer/navigation was handled, false at root.

- [ ] Add failing tests for one full-width information panel, one header back action, four labeled tabs, channel opening from Novedades and back priority across overlays/details/chat/root.
- [ ] Render digit-only names with existing shaper, inspect glyph selection and establish a failing width regression before changing font precedence.
- [ ] Implement text-first font selection preserving emoji shaping, mobile full-width details and root back delegation; keep desktop panel behavior.
- [ ] Implement four labeled tabs and combined Novedades using existing status/channel data/actions; expose settings via top menu.
- [ ] Render 320/390 dp, landscape, keyboard-sized viewport and large text; inspect actual element bounds, headers and phone digits, then run UI regression suite.
- [ ] Commit mobile UX changes.

## Task 5: Spanish UI and connection behavior

**Files:** `internal/i18n/locales/es.po`, `i18n.go`, tests; `internal/ui/info.go`, `contactinfo.go`, `format.go`, `voicerecord.go`, `dialog.go`, affected mobile pages; `internal/wa/backend.go`, backend connection tests.

**Interfaces:** Use existing `Localizer.Text` and `Textf` at UI-owned copy sites. Dynamic dates/quantities use explicit locale formatting. Do not translate all label arguments indiscriminately.

- [ ] Add failing catalog/UI tests for strings visible in screenshot, tabs, permission/attachment errors, recording states, dates and reconnect states; assert user data remains unchanged even when equal to catalog keys.
- [ ] Localize UI-owned strings and formatted messages; audit remaining user-visible English in mobile flows.
- [ ] Trace disconnected sending with backend tests; assert no false successful receipt and draft preservation. Change reconnect/send handling only for demonstrated failures.
- [ ] Run localization, backend and UI tests; inspect Spanish information screen and English-language switching.
- [ ] Commit localization and any evidenced connection fix.

## Task 6: APK validation and workflow inspection

**Files:** `.github/workflows/build.yml`, Android test/build documentation in `docs/android-validation.md`.

**Interfaces:** Keep existing build artifact name `OpenWA-android.apk`; report workflow run URL, commit SHA, jobs and artifact status.

- [ ] Run `gofmt`, `go mod verify`, `go vet ./...`, `go test ./...`, `go build ./...`; resolve introduced failures.
- [ ] Build both Android ABIs with current gogio flags; inspect permissions, libraries, package ID and signature with aapt/apksigner/unzip.
- [ ] Install on available emulator and exercise Task 2–5 flows; log evidence and limitations. Do not equate static APK checks with end-to-end WhatsApp delivery.
- [ ] Inspect GitHub workflows using authorized credentials without logging their value; identify runs for the actual implementation commit and inspect failed job logs.
- [ ] If remote build requires publishing changes, prepare a reviewable branch and report the required publication step; do not silently claim remote validation for unpublished local code.
- [ ] Commit verification documentation and build fixes; deliver available APK and concise test report.

## Self-review

All design sections map to tasks above. Android bridge lifecycle is a prerequisite
for picker and permission flows; UX and localization preserve existing model APIs.
Baseline toolchain availability and device access are execution prerequisites, not
evidence of app functionality. No product code was changed during planning.
